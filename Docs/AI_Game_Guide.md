# Make a game with SANAD — the AI/agent guide

> **This is a native C++23 + Vulkan engine.** A game is a `.nfproj` project,
> `.nfscene` text scenes, Lua gameplay, and `NFPlayer.exe`. It is **not** an
> HTML/JS project. Do not create `index.html`, `package.json`, a web server, or
> a Unity/Godot project — those are not SANAD games.

This guide is deliberately executable: every command below can be run, and the
example at the end produces a small playable game.

---

## 1. Build once

From the engine repository root:

```bat
build_nf.bat Release
```

If that succeeds, you have:

```
build\Release\bin\nf.exe
build\Release\bin\NFPlayer.exe
build\Release\bin\SANADEditor.exe
build\Release\bin\NFAssetCooker.exe
```

`nf` is the project CLI; the editor is optional for agents.

---

## 2. Create the project

```bat
build\Release\bin\nf.exe new Games\CrateHunter --name CrateHunter --template ThirdPerson
```

This copies a playable Third-Person starter. The generated `AGENTS.md` inside
the project repeats the rules in this file.

Useful commands:

```bat
:: cook + package into Games\CrateHunter\dist
build\Release\bin\nf.exe build --project Games\CrateHunter\CrateHunter.nfproj

:: build + launch the player window
build\Release\bin\nf.exe run --project Games\CrateHunter\CrateHunter.nfproj

:: headless acceptance (no window; exits by itself)
build\Release\bin\nf.exe run --project Games\CrateHunter\CrateHunter.nfproj --frames 120 --headless --validation

:: open in the editor
build\Release\bin\SANADEditor.exe --project Games\CrateHunter\CrateHunter.nfproj
```

Acceptance is **exit code 0** and, for the headless run, `Validation errors: 0`
in the log. "The files exist" is not acceptance.

---

## 3. The files that make the game

```
Games/CrateHunter/
  CrateHunter.nfproj
  Content/
    Scenes/Main.nfscene      # entities + components (plain text)
    Scripts/player.lua       # gameplay (update(dt))
    Materials/*.nfmat        # base_color / metallic / roughness
    Meshes/*.nfmesh          # cooked meshes
  Cache/                     # generated by cook (git-ignored)
  dist/                      # generated by build (git-ignored)
```

The startup scene is `Content/Scenes/Main.nfscene`. The project descriptor
(`.nfproj`) points at it. Do not replace the descriptor with a web manifest.

### Scene format

```
# SANAD Scene v1
version: 1
name: Main
entity_count: 3
---
entity: 1:0
  Name: MainCamera
  Transform: local(0,4,8) world(0,4,8) rot(0,0,0) scale(1,1,1) parent(4294967295:0)
  Camera: fov=60 aspect=1.7777778 near=0.1 far=1000 active=true
---
entity: 2:0
  Name: Player
  Transform: local(0,1.2,0) world(0,1.2,0) rot(0,0,0) scale(1.2,1.2,1.2) parent(4294967295:0)
  Mesh: asset_id=3d8f8b09-3e06-448e-94d4-c4c5a1921bc6 material=content://Materials/Player
  Script: lang=lua path=content://Scripts/player.lua
---
entity: 3:0
  Name: CrateA
  Transform: local(2.5,0.75,2.5) world(2.5,0.75,2.5) rot(0,0,0) scale(1.5,1.5,1.5) parent(4294967295:0)
  Mesh: asset_id=f04e488b-4dc8-414b-baee-e3c50e8829ad material=content://Materials/Crate
```

Rules:

- `entity_count` must equal the number of `entity:` blocks.
- `parent(4294967295:0)` means "no parent".
- Keep the camera's view in mind: a static camera at `(0,4,8)` looking at the
  origin sees roughly the central 20×20 area. Keep gameplay there unless you
  also change the camera.
- Asset ids are UUIDs from `Content/AssetRegistry.nfreg`; reuse the ids that the
  template ships with rather than inventing new ones.

## 4. Lua gameplay API

Every script must define `update(dt)`. `dt` is seconds since the previous frame.

| Call | Meaning |
|:---|:---|
| `self_id, self_gen` | the entity running this script |
| `nf.self()` | `id, gen` |
| `nf.entity_pos(id, gen)` | `x, y, z`, or `nil` when the entity has no Transform |
| `nf.set_entity_pos(id, gen, x, y, z)` | move the entity; returns bool |
| `nf.entity_alive(id, gen)` | is the entity still alive |
| `nf.find_entity("CrateA")` | `id, gen`, or `nil` |
| `nf.entity_name(id, gen)` | name string, or `nil` |
| `nf.entity_count()` | live entity count |
| `nf.action("move_forward")` | held? `move_forward`, `move_back`, `move_left`, `move_right`, `jump`, `sprint`, `interact` |
| `nf.axis("move_x")` | -1..1; `move_x`, `move_z` |
| `nf.clamp(v, lo, hi)` / `nf.lerp(a,b,t)` | math helpers |
| `print(...)` | write to the engine log |

Sandbox: no `io`, `os`, `require`, `dofile`, `loadfile`; standard `math`,
`string`, `table`, `utf8`, `coroutine` are available.

## 5. Complete playable example: Crate Hunter

Replace `Content/Scripts/player.lua` with:

```lua
-- Crate Hunter: move with WASD/arrows, touch the crates to score.
local speed = 4.0
local score = 0
local targets = { "CrateA", "CrateB" }
local won = false

function update(dt)
    local x, y, z = nf.entity_pos(self_id, self_gen)
    if not x then return end

    local mx = nf.axis("move_x")
    local mz = nf.axis("move_z")
    nf.set_entity_pos(self_id, self_gen,
        x + mx * speed * dt,
        y,
        z + mz * speed * dt)

    for _, name in ipairs(targets) do
        local id, gen = nf.find_entity(name)
        if id then
            local tx, ty, tz = nf.entity_pos(id, gen)
            if tx then
                local dx, dz = tx - x, tz - z
                if dx * dx + dz * dz < 1.5 * 1.5 then
                    nf.set_entity_pos(id, gen, 0, -50, 0) -- collected
                    score = score + 1
                    print("score", score)
                end
            end
        end
    end

    if score >= #targets and not won then
        won = true
        print("YOU WIN")
    end
end
```

Attach it to the `Player` entity:

```
Script: lang=lua path=content://Scripts/player.lua
```

Build and run:

```bat
build\Release\bin\nf.exe run --project Games\CrateHunter\CrateHunter.nfproj
```

Expected: the blue sphere moves with WASD/arrows; touching each orange crate
logs `score 1`, then `score 2`, then `YOU WIN`. The crates are moved below the
world instead of destroyed because destroying the entity a script is iterating
is a runtime concern; moving it is deterministic and enough for a demo game.

## 6. Visual changes without art tools

Materials are text files:

```
# SANAD Material v1
name: Crate
base_color: 0.58 0.32 0.14 1
metallic: 0
roughness: 0.70
ao: 1
emission: 0 0 0
emission_strength: 0
```

Assign with `material=content://Materials/Crate` on a `Mesh:` line. The
Third-Person template ships `Player`, `Crate`, `Spinner`, `Ground`, `Ball`.

To add a prop, duplicate an entity block, give it a fresh `entity:` id and name,
change its Transform, and bump `entity_count`. A mesh asset id can be reused by
many entities.

## 7. Common failure modes

| Symptom | Cause | Fix |
|:---|:---|:---|
| You created `index.html` / a web game | wrong engine | delete it; make a `.nfproj` project with `nf new` |
| `nf: no .nfproj found` | wrong directory | pass `--project <path>` or `cd` into the project |
| Player opens and closes instantly | run used `--frames` | remove `--frames` for interactive; keep it for tests |
| Script does nothing | no `update(dt)` | define it; check the log for compile errors |
| Entity does not move | no Transform, or id/gen stale | check `nf.entity_pos` isn't nil |
| Scene fails to load | `entity_count` mismatch or bad component line | fix the header; read the loader warning naming the key |
| Build can't find `nf.exe` | engine not built | run `build_nf.bat Release` first |
| Newly built exe blocked (4551) | Windows Smart App Control/WDAC | sign/allow the build; do not disable security, and do not switch to HTML |

---

## 8. What not to do

- Do not add npm/web dependencies to a native game project.
- Do not edit `Engine/` to make a gameplay change; use scene + Lua first.
- Do not claim success from a written file. Run the headless acceptance and
  read the log.
- Do not commit `Cache/` or `dist/` (the generated `.gitignore` covers them).

The engine is small on purpose; a game that runs is worth more than a large
design document that does not.
