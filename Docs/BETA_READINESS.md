# SANAD Engine — Beta Readiness

**تاريخ التدقيق:** 2026-10-18  
**الهدف:** الوصول إلى إصدار Beta Windows x64 قابل للإطلاق بسرعة، مع جودة عالية ومسار استخدام واضح.

## الحالة الحالية

المشروع يملك أساسًا قويًا وقابلًا للبناء: C++23، Vulkan، محرر مستقل، أدوات `nf`، Asset Cooker، Player، قوالب مشاريع، فيزياء Jolt، Lua/C#، صوت، AI، شبكات، ومجموعة اختبارات واسعة. البناء الحالي في `build/video` نجح دون أخطاء (`cmake --build ...`، لا توجد أعمال معلّقة).

## أدلة التشغيل المنفذة

- `CoreTests`: 72 ناجحة، 0 فشل.
- `ECSTests`: 33 ناجحة، 1 متجاوزة اختياريًا لاختبار مليون كيان.
- `AssetTests`: 95 ناجحة، 0 فشل.
- `RuntimeTests` و`EditorTests` و`GameplayTests` و`RHITests` وأدوات الاختبار شُغّلت من الملفات التنفيذية الحالية دون ظهور فشل في الجولة.
- `SANADEditor.exe --headless --frames 30`: خرج بنجاح، رسم Geometry، وحقق `Validation errors: 0` و`Alive RHI objects before shutdown: 0`.
- `NFAssetCooker`: نجح وأفاد بأن الأصل غير متغير.
- `NFSampleBasic3D`: نجح لمدة 30 إطارًا.
- `cmake --build build/video --parallel 4`: نجح، ولا توجد أعمال معلّقة.

## تقدم العمل في هذه الجلسة

- تم إصلاح `configure_release.bat` و`build_release_all.bat`: لم يعودا يفرضان Visual Studio 18 أو يمسحان `PATH`، وأصبحا يكتشفان CMake وVS 2022 Build Tools المدعومين.
- تم بناء Release كامل بنجاح، ونتجت 45 ملفات تنفيذية.
- تم تفعيل هوية الإصدار `0.2.0-beta.1` من `CMakeLists.txt` كمصدر واحد.
- تم إنشاء الحزمة المحمولة `dist/SANAD-0.2.0-beta.1-Windows-x64-Portable.zip` بحجم يقارب 5.8 MB.
- تم اختبار المحرر بعد فك الحزمة من مجلد خارج المستودع. نجح التشغيل، ورسم Geometry، وظهر مسار الشيدر المحلي `Shaders/Basic3D`، مع `Validation errors: 0` و`Alive RHI objects before shutdown: 0`.
- تم إصلاح أولوية مسارات الشيدرز في المحرر وRuntime حتى لا تعتمد الحزمة على مسار build مطلق موجود على جهاز المطور.

## ما يمنع إعلان Beta الآن

### P0 — يجب إغلاقه قبل الإعلان

- تم تثبيت تعريف الإصدار والـ Beta في مسار واحد (`0.2.0-beta.1`) والتحقق من ظهور الاسم في الحزمة؛ ما زال يجب التحقق من خصائص الملف والمثبت عند بناء Installer.
- تم بناء Release وإنشاء Portable والتحقق منه؛ ما زال Installer نفسه يحتاج بناء Inno Setup واختبار تثبيت/إزالة.
- اختبار المسار الكامل لمستخدم جديد: تشغيل المحرر، إنشاء مشروع، فتحه، طبخ الأصول، تشغيل Player، وإعادة فتح المشروع من مسار مختلف.
- تم التحقق من أن المحرر المحمول يرسم Geometry فعلية؛ يجب إضافة نفس البوابة إلى Player/الحزمة عند اختبار المشروع المنشور.
- اختبار وجود Vulkan، غيابه، ومسار رسالة الخطأ للمستخدم.

### P1 — جودة إطلاق عالية

- جعل إعدادات الإصدار والتغليف قابلة لإعادة الإنتاج بلا مسارات محلية أو ملفات من شجرة التطوير.
- مراجعة تجربة أول تشغيل ووضوح الرسائل العربية والإنجليزية.
- فحص دورة حفظ/تحميل/إغلاق المشروع، وPlay/Stop، وUndo/Redo، وAsset import من واجهة المستخدم.
- إضافة smoke test للحزمة بعد فك الضغط، بدل اختبار ملفاتها فقط.
- تسجيل نتائج الأداء الأساسية وعدم السماح بتراجع واضح في وقت الإطار أو استهلاك الذاكرة.

### P2 — بعد تثبيت Beta

- تحسينات إضافية للمحرر والمظهر والأصول والصوت.
- Demo احترافية مع أصول بصرية وصوتية منظمة، دون تأخير إطلاق النواة المستقرة.

## ملاحظات مهمة

توجد حاليًا تغييرات غير محفوظة في Git مرتبطة بـ Phase 28/29، منها دعم المركبات وتعديلات Runtime والمحرر واختبارات جديدة. لم يتم حذفها أو إعادة ضبطها. تم حفظ نسخة أمان محلية قبل بدء عمل Beta في:

` .work/beta-audit/pre-beta-changes.patch `

والملفات الجديدة غير المتتبعة في:

` .work/beta-audit/untracked/ `

## قرار العمل

لن نضيف نظامًا كبيرًا جديدًا قبل إغلاق P0. الأولوية هي: **Release build → packaging → smoke test للحزمة → مسار المستخدم الجديد → إصلاحات الاستقرار → تحسينات تجربة الاستخدام → Demo → إعلان Beta**.

## معيار إعلان Beta

لا تُعلن النسخة Beta إلا إذا نجحت بوابات البناء، الاختبارات، المحرر headless، إنشاء مشروع جديد، طبخ الأصول، تشغيل Player من الحزمة، التحقق من عدم وجود أخطاء Vulkan أو تسريبات RHI، وفتح/حفظ مشروع من مجلد مستقل.
