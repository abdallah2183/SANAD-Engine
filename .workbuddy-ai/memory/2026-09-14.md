## Independent verification of Phase 9 (Nova, same day)

Rebuilt from scratch into `build/verify` (fresh configure + 229/229 targets, MSVC 14.51.36231,
/W4 /WX). **Test claim reproduced exactly: 420 passed / 0 failed / 1 skipped / 421 across 11
suites** — Core 44, Jobs 4, ECS 25+1skip, Assets 45, RHI 69, Physics 86, Animation 31, Audio 20,
Runtime 28, Editor 54, Tools 14. Phase 7 chain still green: packaged `NFPlayer` from `dist/`,
no `--project`, 120 frames, `meshes=1`, 0 validation errors, 0 leaked RHI objects, exit 0.

**But Phase 9's integration is not done.** The libraries and their unit tests are real and honest;
nothing is wired into the engine:

1. **Animation never runs.** `Runtime::update(dt)` is only
   `m_manager.update()` → `sync_meshes_from_assets()` → `step_physics(dt)` → `propagate_transforms()`.
   No animation step. `AnimationComponent` in a scene is inert — the player is never advanced.
   `last_local_pose` / `last_world_pose` are declared in `Components.hpp` and **written by nobody**.
2. **No skinning / render hookup.** Nothing outside `Engine/Animation` mentions skeleton, bone, or
   pose; the plan's "render path gets the final pose as a mesh override" does not exist. Even a
   computed pose would have nowhere to go.
3. **Audio never runs.** Same — no `AudioComponent` step in `Runtime::update`; only
   `NullAudioDevice` exists. Currently pure math + an ECS struct.
4. **No editor panels** for Animation or Audio. `Editor/src/ui/Panels.cpp` covers Transform, Mesh,
   Camera, Directional Light, RigidBody, Collider, PrefabLink — zero Animation/Audio references.
5. **Phase9_Plan §5 acceptance is unimplemented.** It requires the template scene to gain an
   animated entity and the packaged player to show its transforms changing. The scaffolded scene
   (`Templates/Default/Content/Scenes/Main.nfscene`) is still the Phase 8 five-entity physics scene
   (Camera, Light, Mesh, static Plane, dynamic Box) — no `Animation:` or `Audio:` line — and
   `Tools/Player/main.cpp` has no animation assertion. The §5 chain passes, but only because it
   still tests physics.

`Tests/RuntimeTests/test_runtime_scene.cpp` only asserts save/load **round-trip** of component
fields (`clip_name`, `speed`, `buffer_name`, `volume`, `looping`) — it never asserts that anything
advances them, so the suite cannot catch any of the above.

Verdict given: Phase 9 is **half-done** — module layer complete and trustworthy, integration layer
absent. Do not start Phase 10 (Scripting + Save, `Docs/Phase10_Plan.md`) on top of it; Phase 10's
inspector work would collide with the missing panels, and its "all existing 420 tests + new suites"
baseline would bake in the gap.

Verification artifacts: `build/verify` (clean build, kept), demo package removed. Note the main
OneDrive checkout is still at Phase 6 (`421511f`) — Phases 7–9 remain uncommitted in this worktree.

## Phase 9 — integration gap closed (same day, second pass)

An independent verification pass (`Docs/Phase9_Verification_2026-09-14.md`) found the phase
**half-done**: the module layer was complete and trustworthy, but nothing was wired into the runtime.
`Runtime::update()` never called an animation or audio step, so an `AnimationComponent` in a scene

### What was added

- **Runtime stepping.** `Runtime::update` is now
  `m_manager.update()` → `sync_meshes_from_assets()` → `step_physics(dt)` → `step_animation(dt)` →
  `step_audio(dt)` → `propagate_transforms(world)`. Animation runs after physics so it wins on a
  dual-component entity; audio runs after transforms are final so spatialisation is not a frame late.
- **Real samples without an import pipeline.** The asset importers (mesh/WAV) are explicit Phase 9
  non-goals, so the scene loader previously created an *empty* `AnimationClip{}` (duration 0, no
  tracks) for every `Animation:` line, and `AudioBuffer` had no producer at all. Added
  `make_procedural_clip()` (spin/bob from a `ProceduralClipSpec`) and `make_tone_buffer()` (PCM sine,
  half-scale for headroom). Both are deterministic and unit-tested.
- **Placement / rebase model.** Assigning the root bone's world matrix directly would snap an entity
  to the rig origin. `AnimationComponent` now stores an authored base offset and
  `Runtime::rebase_animation()` re-anchors it; `step_animation` applies the posed delta *relative* to
  the entity's transform. The editor's `set_transform` calls `rebase_animation()` so a hand-edit is
  not undone on the next frame.
- **Scene format.** `Animation:` gained `procedural=`, `axis=`, `turns=`, `amplitude=`, `duration=`,
  `loop=`; `Audio:` gained `tone=`, `tone_duration=`. The loader calls `player.play()` when the scene
  does not say `paused=true` — without it the player sits at t=0 forever, because
  `AnimationPlayer::update()` returns early unless the state is `Playing`.
- **Editor.** `EditorApp::set_animation` / `set_audio` plus two inspector panels in `Panels.cpp`
  (Animation, Audio), following the Phase 8 `InspectorCache` pattern.
- **Acceptance.** Template scene gained entity 6 (Mesh + `Animation:` + `Audio:`); `Application.cpp`
  tracks the animated entity's max transform deviation and **exits 1** if it never moved.
