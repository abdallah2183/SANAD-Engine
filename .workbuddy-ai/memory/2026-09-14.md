### What was added

- **Runtime stepping.** `Runtime::update` is now
  `m_manager.update()` → `sync_meshes_from_assets()` → `step_physics(dt)` → `step_animation(dt)` →
  `step_audio(dt)` → `propagate_transforms(world)`. Animation runs after physics so it wins on a
  dual-component entity; audio runs after transforms are final so spatialisation is not a frame late.
- **Real samples without an import pipeline.** The asset importers (mesh/WAV) are explicit Phase 9
  non-goals, so the scene loader previously created an *empty* `AnimationClip{}` (duration 0, no
  tracks) for every `Animation:` line, and `AudioBuffer` had no producer at all. Added
  `make_procedural_clip()` (spin/bob from a `ProceduralClipSpec`) and `make_tone_buffer()` (PCM sine,
  half-scale for headroom). Both are deterministic and unit-tested.
- **Placement / rebase model.** Assigning the root bone's world matrix directly would snap an entity
  to the rig origin. `AnimationComponent` now stores an authored base offset and
  `Runtime::rebase_animation()` re-anchors it; `step_animation` applies the posed delta *relative* to
  the entity's transform. The editor's `set_transform` calls `rebase_animation()` so a hand-edit is
  not undone on the next frame.
- **Scene format.** `Animation:` gained `procedural=`, `axis=`, `turns=`, `amplitude=`, `duration=`,
  `loop=`; `Audio:` gained `tone=`, `tone_duration=`. The loader calls `player.play()` when the scene
  does not say `paused=true` — without it the player sits at t=0 forever, because
  `AnimationPlayer::update()` returns early unless the state is `Playing`.
- **Editor.** `EditorApp::set_animation` / `set_audio` plus two inspector panels in `Panels.cpp`
  (Animation, Audio), following the Phase 8 `InspectorCache` pattern.
- **Acceptance.** Template scene gained entity 6 (Mesh + `Animation:` + `Audio:`); `Application.cpp`
  tracks the animated entity's max transform deviation and **exits 1** if it never moved.

### W5 DONE — world-streaming seam
- `NF/Scene/StreamingVolume.hpp` — `ChunkCoord`, `StreamingVolume`, `chunk_at`, `chunk_center`,
  `distance_to_chunk`, `chunks_in_radius`, `std::hash<ChunkCoord>`.
- `NF/Runtime/WorldStreamer.hpp/.cpp` — range + hysteresis + per-update load cap + load/unload callback

Three decisions worth keeping:
1. **Distance to the chunk's AABB, not its centre** — a centre distance makes a chunk's range depend on
   where inside it the player stands, so it can fall out of range while they stand on it.
2. **`chunk_at` floors, does not truncate** — truncation maps `-0.5` and `+0.5` into cell 0.
3. **`chunks_in_radius` returns nearest-first, tie-broken by coordinate.** Found by a *failing test*,
   not designed: the first version sorted by coordinate, and with a load cap that deferred whatever sat
   at high x, the streamer would load the far side of the region before the ground under the player.
   **Order is load-bearing wherever a cap exists.**
- `effective_unload_radius()` clamps an inverted band up to `load_radius`; without it an inverted band
  unloads the chunk just loaded, every frame, forever.
- Rule 0 verified: removing the hysteresis fails `streamer_does_not_thrash_on_a_boundary` on
  `unload_calls != 0`.

### NEW FINDING — a third duplicate type: two `Mat4`s
`nf::Mat4` (Core, `f32 m[4][4]`, row-major) vs `nf::rendering::Mat4` (Camera.hpp, `float m[16]`,
column-major). Same name, different layout, different translation slot (`m[3][0..2]` vs `m[12..14]`).
`RenderObject::world` is the rendering one — which is why `ro.world.m[12] = x` compiles and is correct.
The danger is that they look interchangeable: a `reinterpret_cast` or `memcpy` between them silently
transposes every transform, with nothing in the type system objecting. Rendering also has its own
`Vec3`, hence `Runtime.cpp`'s `from_rendering()` converter.
Same class of defect as the two `.nfmesh` formats and the two euler conventions. **Not fixed yet** —
it needs the same "one type, one owner" treatment W1 needs.

### NEW FINDING — `Runtime::load_scene` replaces the world, so it cannot stream
W5's seam is complete, but the handler that loads a chunk needs to **merge** a scene into the live
world, and that operation does not exist. It belongs next to the scene loader, where the component
list already lives, so the merge cannot drift from the parser.
