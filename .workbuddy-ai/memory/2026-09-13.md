### The deciding evidence

`Tools/BuildTool/` is an empty `.gitkeep`. So Phase 7 = **close the shipping loop**

### Root causes found while grounding the plan (these are the real work)
1. **`Application::run()` guesses its project by walking up the filesystem** looking for a dir with
   BOTH `Engine/` and `Content/` (`Application.cpp:39-52`) — the *engine source tree* layout. A
   shipped game has neither, so it cannot run at all. `ApplicationConfig` has no project field.
2. **`Tools/AssetCooker/main.cpp:66-111` makes the same assumption** (walks up for `CMakeLists.txt` +
   `Engine/`), and cooks **one asset per invocation** — no cook-all.
3. **`Runtime::resolve_shader_dir()` (`Runtime.cpp:93-128`) hardcodes six build-tree paths** incl.
   `build/DebugNinja/Shaders/Basic3D`. **This is the most likely thing to break the first standalone
   build**, which is why the descriptor adds a `shaders://` mount.

### Deliverable
`Docs/Phase7_Plan.md` — goal, grounded current state with file:line, design (descriptor format,
`shaders://` mount, package layout as plain dirs not an archive, CLI surface), W1–W8 work breakdown
with per-item acceptance, end-to-end acceptance, risks, **explicit non-goals**, carried-over debt.

### W1 done — `ProjectDescriptor`
`Engine/Assets/{include/NF/Assets/ProjectDescriptor.hpp, src/ProjectDescriptor.cpp}`.
Line-based tolerant format matching `.nfreg`/`.nfmat`/`.nfscene` (no JSON parser exists in the
project, and adding one would be inconsistent). 14 tests in
`Tests/AssetTests/test_project_descriptor.cpp`. **Full suite 225 passed / 0 failed / 1 skipped / 226**
(AssetTests 13 → 27).

Design points worth keeping:
- Four default mounts relative to the project root (`project://`, `content://`, `cache://`,
  `shaders://`); explicit declaration overrides. **`engine://` has no default** — it only means
  anything in the engine source tree.
- Relative mounts may not escape the project root (`..` rejected) — but absolute is allowed, so
  `engine://` can point at an install. It is never *derived* from a traversal.
- Unknown keys ignored (an older engine opens a newer file); unknown `version` **rejected**, not
  half-parsed.
- `save_to_file` writes mounts relative to the root when they live inside it, so a project directory
  is **relocatable** — pinned by `project_descriptor_is_relocatable`.
- `apply_mounts` names the failing mount; "VFS setup failed" is useless with five mounts.

**Plan-vs-implementation correction:** the plan first said "missing `content://` is an error"; the
implementation defaults all four. Updated the plan to match rather than leave a doc that lies.

### Next
W2 — `Application` consumes the descriptor (optional; the current walk-up stays as the fallback so
samples/tests/CI keep working), and `resolve_shader_dir()` consults `shaders://` first.

### The decisive proof (highest risk in the plan, now retired)
Package relocated to a different directory, engine's `build/debug/Shaders` renamed away, player run
with **no `--project`**: exit 0, `meshes=1`, 0 validation errors, 0 leaks. The hardcoded
`build/DebugNinja/Shaders/Basic3D` paths are no longer load-bearing.

### Three real bugs the new tests caught (none were in the plan)
1. **Stale assets survived a rebuild.** `nf build` copied the whole `Cache/`, so a deleted source
   asset stayed in the package. Fixed by pruning in `cook_all` (registry entry + cooked file).
   Caught by `packager_rebuild_does_not_leave_stale_files`.
2. **`cooked_path_for` glued paths together.** `"cache://Packed" + "M/x"` → `cache://PackedM/x`.
   Caught by a test I wrote asserting the separator.
3. **The CI script was broken in two ways** — relative `$BUILD_DIR` after `cd`, and it ran the build
   tree's player instead of the **packaged** one (which then looked for a `.nfproj` beside the wrong
   exe). Both found by running the CI script locally before trusting it. **Always run a CI script
   locally once.**

### Also found and cleaned
`Content/Meshes/corrupt.nfmesh` (21 bytes, initial commit, referenced by nothing) and
`Content/Shaders/dummy.frag` (a text file containing the literal characters `\x03\x02...`, with a
registry entry pointing at a cooked path nothing produces) were in the shippable content tree.
Moved to `Tests/fixtures/`; the stale shader registry entry removed, so `nf verify` on the engine's
own content now passes. **Reversible with `git mv`.**

Also confirmed a pre-existing issue worth remembering: **two incompatible `.nfmesh` formats** —
`Assets/MeshAsset` writes magic `NFME`, `Rendering/MeshAsset` writes `NFM1`. `Content/Meshes/cube.nfmesh`
is `NFME`, so test fixtures must use `assets::MeshAsset::from_static_mesh(...)::save_to_file`, not
`rendering::mesh_asset::save_mesh_asset`.
