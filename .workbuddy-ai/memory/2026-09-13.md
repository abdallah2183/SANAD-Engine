### Bugs found (all reproduced)
1. **CRITICAL — stale framebuffer cache → SIGSEGV.**
   `Renderer3D.hpp:217-229` keys `m_tonemap_fbs` on the raw `const rhi::Texture*` **address**.
   Cleared only in `destroy_resolution_dependent()` (Renderer3D.cpp:406,414), and
   `Renderer3D::resize()` early-returns on unchanged size (Renderer3D.cpp:424). So replacing the
   render target with a new texture of the *same size* → allocator recycles the address → cache
   hit → framebuffer built for the destroyed texture → dead `VkFramebuffer` in
   `vkCmdBeginRenderPass` → crash.
   Crashes: `material_albedo_gpu_effect`, `material_params_gpu_effect`,
   `hotreload_mesh_rebuilds_live`. All use a helper that creates a fresh 64×64 target per call
   while reusing one `Runtime`.
   Also: `Renderer3D.cpp:752` stores a possibly-null framebuffer and dereferences it unguarded
   at line 756.
   This violates the design doc's own "handle-based resources, no raw pointers" rule.
2. **HIGH — Triangle sample not validation-clean.** `Samples/Triangle/main.cpp:228-232` never
   sets `rp_desc.present_source = true` (default false, RHI.hpp:271) → one
   `vkQueuePresentKHR` layout error per frame. The "Validation: CLEAN" milestone claim does not
   hold for the sample. Sample also has no pixel verification.
3. **MEDIUM — false test failure.** `test_viewport.cpp:140` asserts `res.target.get() != first`
   after `res.reset()` destroyed `first`; the allocator recycles the address. Encodes an
   allocator detail as a contract.
4. **LOW** — GpuFixture reports `validation: off` while validation messages are emitted.
5. **LOW** — Benchmarks can't catch regressions: `benchmark_1m_entities` reports `[OK]` without
   running unless `NF_BENCH_1M=1` (green by skip), and all benchmark output goes through
   `NF_LOG_INFO` which `TestFramework.cpp` suppresses (min level = Warn). No thresholds.
6. **LOW** — No CI config, and **the project is not a git repository**.

### What changed
- **Framebuffer cache (the crash).** Abdal had already swapped `TonemapFBKey` to
  `rhi::Texture::creation_serial()`. I added the missing pieces: a null-check on
  `create_framebuffer` before the deref in `Renderer3D.cpp`, and a bound on the cache
  (`kMaxTonemapFramebuffers = 8`) because serial keys fix invalidation-by-reuse but introduce
  unbounded growth — nothing tells the renderer a texture died.
- **`present_source = true`** in `Samples/Triangle/main.cpp` and `Samples/TexturedQuad/main.cpp`
  (TexturedQuad had the same bug, not in the original report).
- **`test_viewport.cpp`** now compares `creation_serial()` instead of a recycled pointer.
- **Test honesty.** Added `NF_SKIP` + a `Skipped` bucket to the framework; `require_gpu()`
  replaced 58 silent `if (!f.available) return;` early-returns; 11 silent returns on missing
  shader assets became skips; `benchmark_1m_entities` SKIPs instead of reporting OK without
  running; `NF_TEST_LOG_LEVEL` exposes benchmark timings (previously invisible because the
  runner forced level Warn). Framework `Total:` now counts tests actually run, not all registered.
- **GpuFixture** reports the device's real validation state via `validation_enabled()` — it used
  to print "off" while validation was on.
- **Git + CI.** Repo initialised (3 commits on `main`), `.gitignore`/`.gitattributes`,
  `Scripts/run_tests.sh`, `.github/workflows/ci.yml` (installs Lavapipe so GPU suites run
  headlessly rather than skip).

### Bugs found in Abdal's concurrent work
He was editing while I worked. Two of his in-flight changes were broken and are now fixed:
1. `vkResetDescriptorPool` was added to `NF_VK_DEVICE_FUNCS` but never to the **hand-written
   load list** in `VulkanLoader.cpp` → null function pointer → SIGSEGV in
   `rhi_descriptor_allocator_grows_and_resets`. **The X-macro only declares and zero-initialises;
   loading is a separate list.** This is a real design fragility worth remembering.
2. `generate_mipmaps` existed in `RHI.hpp` and `CommandBuffer_Vk.cpp` but `VulkanCommandBuffer`
   never declared the override → abstract class → NFRHI did not compile.
3. `rhi_descriptor_allocator_grows_and_resets` asserted the old destroy-and-recreate contract;
   updated for pool recycling.

### Git lesson

### Corrections to the report
- **"202/202" is not accurate.** Measured: **204 passed / 0 failed / 1 skipped / 205 registered**
  (Editor is 53, not 50). The gap is the 1M-entity benchmark: it reports SKIPPED, and counting it
  as a pass is the same green-by-skip error that made the original "all green" claim false.
  `ctest`'s "100% tests passed" hides this too — a suite exits 0 with a skip.
- **"UI overlay: 60581 pixels differ" is not a stable number.** Measured **80,445** on the same
  build. The value depends on viewport size, so the meaningful proof is "the overlay provably
  drew", not the figure.

### ⚠️ New finding — the acceptance cannot run `--headless`
`--scene ... --frames 120 --validation --headless` → **exit 1, 6 FAILED**, failing at
`Drop imported mesh` and cascading through all prefab steps. The texture import/hot-reload steps
still pass. Headless renders a smaller viewport (3,290 lit px vs 13,259 windowed) and the drop
step fires ~2 ms after `Mesh import submit OK` vs ~39 ms windowed — i.e. the import has not
landed yet (mechanism is a hypothesis; the failure is not).
**Consequence: CI cannot gate the editor acceptance as written.**

### Diagnosability gap
`auto_check(...)` logs only `OK` / `FAILED` with no reason, and emits no WARN/ERROR. Also
`--scene` is mandatory: omitting it fails 9 steps with zero explanation (I misdiagnosed it as a
regression on my first run). Both are worth fixing.

### Lesson
Read the documented invocation before declaring a regression. `Editor/PRODUCT.md` states the
exact acceptance command; I ran a variant and got a false negative.
